Equivox

Browser control by voice

Speak a browser task. Equivox starts with the first complete command while you continue talking.

01

Equivox controls a real Chromium browser through Playwright. Apple Speech transcribes microphone audio on the Mac. Jev interprets partial transcripts. The system aims to act on complete clauses during speech. Source: README.md, main.py, audio/apple_speech/main.swift, backend/model.py.

How Equivox works

01

Speech

Apple Speech sends partial transcripts as the user talks. Typed commands enter the same loop.

02

Page context

The browser exposes visible controls, field labels, focus, and recent actions.

03

Decision

Jev chooses an action and an observed target, then judges whether the command is ready.

04

Execution

Python checks the decision. Playwright performs the action and refreshes the context.

03

Audio transcription runs on device by default. Transcript text and page context go to the configured Jev endpoint through OpenRouter. Optional screenshots also leave the device when vision is enabled. The default path uses text and DOM observations. Sources: audio/apple_speech/main.swift, audio/apple_transcriber.py, backend/model.py, backend/jev.py, perception/perceive.py, executor/act.py.

Acting during speech

Regular decision checks

An 80 ms scheduling window prevents continuous partials from postponing every decision.

Complete clauses can execute

Equivox can open a tab before the user finishes the rest of the request.

Growing queries wait

Search and typed text wait for a clear boundary, a finished transcript, or enough quiet.

Each action updates the page

The next command uses fresh context. Executed words leave the pending transcript.

06

The scheduler defaults to one model call in flight. It coalesces partials without cancelling useful inference. Free-text payloads normally require a bounded following command, a final transcript, or 600 ms of quiet. Audio activity guards against stalled recognition being mistaken for silence. Semantically incomplete commands remain waiting. Confirmation gates cover destructive actions. Sources: backend/scheduler.py, backend/policy.py, main.py, audio/apple_speech/main.swift.

07

Local results recorded on 2026-11-08. The seven-case final synthetic probe produced five executable decisions and waited on two incomplete fragments. It measured decision-call duration, including the first connection, with a median of 187 ms and range of 177–406 ms. Seven samples cannot establish p95 or general accuracy. The final offline pytest run passed 294 tests. Source: refactor-plan.md, scripts/benchmark_decisions.py, final test run in the project session.

What still needs work

Real speech measurement

Replay actual recognition updates and measure when each action starts.

Noise and corrections

Test hesitation, changing words, and different microphone conditions.

Complex page controls

Improve custom dropdowns, rich editors, and interfaces drawn on canvas.

Visual grounding

Evaluate the optional screenshot path on controls that DOM text cannot explain.

08

These are development priorities, not completed capabilities. Vision is opt-in and currently lacks live accuracy calibration. Closed shadow roots, canvas interfaces, virtualized options, and editor-specific event protocols remain limited. Clause segmentation also cannot always distinguish an unquoted literal command from an instruction connector. Source: refactor-plan.md, perception/perceive.py, executor/act.py, backend/clauses.py.
